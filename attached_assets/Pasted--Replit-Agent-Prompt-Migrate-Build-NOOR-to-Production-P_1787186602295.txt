## PROMPT START

We are migrating this NOORÉ e-commerce prototype to a different stack before continuing feature work. Do not skip the migration and do not silently keep the old stack "because it already works" — I need the target stack specifically.

### What to KEEP as-is

- The overall npm workspace monorepo structure (`artifacts/*`, `lib/*`)
- The visual design system in `index.css` (colors, typography, editorial black/white NOORÉ look) — do not redesign this

### What to MIGRATE

1. **Frontend: React + Vite → Next.js (App Router)**
   - Recreate `artifacts/dtc-storefront` as a Next.js app
   - Port over the existing pages/components and Tailwind styling, converting Wouter routes to Next.js App Router file-based routes
   - Break up the current monolithic `App.tsx` into proper per-route files and reusable components (Header, Footer, ProductCard, VariantSelector, CartDrawer, etc.) — do not keep it as one giant file
   - Replace `localStorage`-only cart/wishlist with state that will later sync to a real user account (keep localStorage as a guest-cart fallback only)

2. **Database: PostgreSQL + Drizzle → MongoDB + Mongoose**
   - Remove the Drizzle/`node-postgres`/`DATABASE_URL` setup in `lib/db`
   - Set up a MongoDB connection (I'll provide a MongoDB Atlas connection string as `MONGODB_URI`) using Mongoose
   - Do NOT invent schemas ad hoc. Use exactly these models (I'll paste them next as separate files): `User`, `Product` (with optional embedded `variants[]` for color/size/sku/stock), `Order` (with snapshotted `items[]`, `paymentMethod` enum of `sslcommerz`/`cod`, `paymentStatus` enum), `Coupon`

3. **Backend: Express 5 API server**
   - Keep Express, keep the `/api` mount point, keep Pino logging
   - Replace the placeholder `/api/healthz`-only setup with real routes once models are in place (I'll direct this phase by phase — do not build all routes at once)

### What is currently MISSING and must be built (do not treat these as "already done")

- Authentication (Better Auth, customer + admin roles) — currently zero auth exists
- Real product CRUD connected to MongoDB — currently local mock data only
- Real cart tied to backend/session — currently `localStorage` only
- Real checkout that creates an actual `Order` document — currently a non-functional form
- SSLCommerz + COD payment processing — currently just UI buttons with no logic behind them
- Real admin dashboard reading live data — currently hardcoded fake numbers
- Server-side price/stock validation on checkout — does not exist yet

### Engineering rules for everything going forward

1. Validate all server input (zod or express-validator) — never trust the client, including this frontend.
2. Never expose secrets (`MONGODB_URI`, SSLCommerz keys, auth secret) to the browser.
3. Every admin API route checks role server-side, not just hides UI.
4. Every price/total shown at checkout is recalculated server-side from MongoDB — never trust a client-submitted price.
5. Stock decrements must be atomic (`findOneAndUpdate` with a stock-check condition) to prevent overselling.
6. Consistent API error shape: `{ success: false, message, code? }`.
7. Loading/empty/error states on every data-driven page.
8. No `TODO` placeholders in checkout, payment, or stock logic — these must work fully even with placeholder images.

1. Confirm migration plan and ask any clarifying questions before touching code

5. Connect product catalog pages to real MongoDB data (replace mock `products.ts`)
6. Real cart (backend/session-based, replacing localStorage-only)
7. Real checkout: creates an `Order`, server-side price/stock validation
8. SSLCommerz sandbox integration + IPN handling (idempotent) + COD as alternate method
9. Real admin panel: product CRUD, order management, coupon CRUD, live dashboard numbers
